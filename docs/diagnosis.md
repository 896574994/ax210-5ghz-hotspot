# Intel AX210 插网线时开不了 5GHz 热点：排查全过程与一个可用绕行

> 结论先行：不是网卡坏了，也不是驱动版本落后。单射频网卡在没有现成 5GHz 信道可用时，拒绝自己起 AP。

## 一、现象

笔记本无线网卡为 Intel Wi-Fi 6E AX210，出现两种不同结果：

- **连着 5GHz WiFi 时**：移动热点选 5GHz，能开，手机可连。
- **只插网线、WiFi 关闭时**：热点选 5GHz 报"所选网络频段不可用"，或停在"正在打开"。

同一张卡、同一个驱动、同一个热点设置，唯一差别是上行方式。

## 二、机制解释

AX210 是单射频卡，同一时刻只能工作在一个频段、一个信道。

连着一个 5GHz 网络时，射频已锁定在某个 5GHz 信道。开热点时驱动让热点用同一信道，客户端与热点分时共用这一套射频。这一点 Intel 文档有说明。

插网线时射频闲置，驱动必须自选 5GHz 信道起 AP，失败就发生在这里。

为什么 2.4GHz 一直正常？2.4GHz 信道只有 1、6、11 几个，规则简单；5GHz 信道多，还要过 DFS 雷达避让与地区法规校验。此条为推断，未定位到驱动内部具体拒绝点。

## 三、试错记录（全部无效）

| 方向 | 做法 | 结果 |
|---|---|---|
| 驱动版本 | 升级至 Intel 官方 24.80.0.2，SHA512 校验一致 | 行为不变 |
| 第三方过滤驱动 | 分别在无线卡与以太网卡解绑 WinpkFilter、Npcap | 无影响 |
| 强制单频 | 无线模式改为「仅 5GHz 802.11a」并重置网卡 | 仍失败 |
| 幽灵适配器 | pnputil 删除 3 个 Unknown 的 Wi-Fi Direct 实例 | 缓解了 2.4G 偶发失败，5G 无效 |

## 四、关键发现：返回码会骗人

最初用 Windows 官方热点接口判断成败，返回码在 Success 与失败之间跳，看着像"偶尔能成"。

改查 WLAN 服务操作日志后才看清：

- **8006**：承载网络已启动，真成功。
- **8007**：承载网络启动失败，错误码 31。

对照时间戳发现，多次接口返回 `Success` 时，日志同期却是 8007。**接口返回码只代表请求被受理，不代表 AP 在广播。**

补充一个反直觉点：热点开着但无客户端连接时，虚拟适配器状态是 `Disconnected` 而非 `Up`，用它判断热点状态会误判。

## 五、可用绕行方案

核心发现：**断开 WiFi 后，承载网络不会被回收，会留在原 5GHz 信道。**

顺序：

1. 先连一个附近 5GHz 网络，把射频引到 5GHz。
2. 以以太网为共享源，请求 5GHz 热点。
3. 断开 WiFi。热点保留，上网走网线。

实测证据：断开后虚拟适配器保持 `Up`，十余秒内无 8007，热点侧取得 `192.168.137.1`（Windows 共享固定地址段）。

代价：每次开热点需重跑一遍；附近无 5GHz 网络时不可用；热点信道随种子网络。

## 六、更彻底的方案

1. 换回原装 Realtek 网卡实测（需验证，暂无数据）。
2. 增加外置 USB 无线网卡专供热点。
3. 购置路由器作 AP，最稳。

## 七、复盘

时间主要浪费在两点：过早相信接口返回码；未意识到"连 5G 才能开 5G"来自单射频物理约束，而非软件缺陷。
